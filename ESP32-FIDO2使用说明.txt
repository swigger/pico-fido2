ESP32-S3 FIDO2 安全密钥使用说明

一、认识设备与程序
设备是一块 ESP32-S3 安全密钥，在电脑上显示为 USB 安全密钥（LibreKeys One）。
  RESET 键：重启设备。
  BOOT 键：确认键。平时插拔设备时不要按住 BOOT（按住 BOOT 插入会进入刷写模式）。
状态灯平时熄灭，只在需要你操作时闪烁：
  绿灯闪烁：设备在等待你确认一次网页登录或注册（按 BOOT 或在程序中确认）。
  蓝灯快闪：正在配对电脑或写入设备设置，等待你按 BOOT。
  红灯闪烁：中转模式下，正在等待安全端电脑上的人工批准。

管理程序有两个版本，功能相同：
  Esp32KeyConfirm：图形界面，支持 Windows、macOS 和 Linux。
  pico-fido-cli：命令行版本，适合终端和脚本。
主窗口顶部选择要管理的设备；“命名设备”可给设备起一个只保存在本电脑上的名字
（最多 32 个 UTF-8 字节，一个汉字通常占 3 字节）。拔出所选设备后程序不会自动换成另一把。
主窗口有三个页签：
  授权与设置：本机授权密钥、配对、设备设置。
  独立模式查询：查看保存在设备里的网站和账号。
  中转模式服务：把这台电脑作为安全端使用。

两种工作模式
  独立工作模式（默认）：网站的登录凭据由设备生成并保存在设备里，和普通安全密钥一样使用。
  中转模式：设备通过 Wi-Fi 把登录和注册请求转给一台你信任的电脑（安全端），
    凭据保存在安全端，每次使用都要在安全端批准。安全端可以在远处，也可以就在旁边。

二、首次使用：配对电脑
1. 插入设备，打开程序，在“授权与设置”页点击“生成本机密钥”。
2. 点击“配对”。设备蓝灯快闪后，先松开 BOOT，再按住约 1 秒后松开。
3. 状态栏显示“设备已连接 · 本机已授权”，“设备中已授权的公钥”列表出现标注“本机”的一项。
配对是双向的：设备记下这台电脑的公钥，电脑也记下设备的公钥。双方的私钥都不会离开各自一端。
若状态显示“未记下设备公钥，请重新配对”，按上面步骤再配对一次即可。
  设备最多保存 4 台电脑的授权。配对不会影响已有的网站账号，拔插后仍然有效。
  配对期间不要在网页上同时使用安全密钥，否则配对会被取消。再次点击按钮可取消配对。
  移除授权：选中列表中的公钥，点击“移除所选授权”，同样需要按 BOOT 确认。
  添加和移除授权都必须实际按 BOOT，程序不能代替。

换电脑：在新电脑安装程序，生成本机密钥并按 BOOT 配对即可，旧电脑仍可继续使用。
本机密钥不能导出或导入，复制程序的数据文件也不能迁移授权。授权数满了时，先移除不再使用的旧电脑。

三、独立工作模式
设置安全密钥 PIN
  Windows：设置 → 账户 → 登录选项 → 安全密钥 → 管理 → 设置 PIN。
  这是安全密钥自己的 PIN，与 Windows Hello PIN、网站密码、备份密码都不同。
  除非你确实想让设备上的所有网站凭据失效，否则不要选择“重置安全密钥”。

登录与注册
  在网页上选择“USB 安全密钥”，按提示输入安全密钥 PIN。设备绿灯闪烁时，任选一种方式确认：
  直接在设备上短按 BOOT；或者在已配对的程序弹出的“独立工作模式 · 确认通行密钥请求”窗口中，
  核对网站后点击“批准本次请求”。关闭这个窗口后仍可在设备上按 BOOT。
  每次确认只对当前这一个请求有效，最长等待 90 秒。程序不会自动确认，也不监听网络。

通过远程桌面使用
  把设备插在被远程控制的那台电脑上，在那台电脑上打开程序和浏览器，按上面的方法在程序窗口中批准。
  如果 Microsoft 远程桌面把安全密钥验证转到了你面前的电脑上，可在 .rdp 文件中加入
  redirectwebauthn:i:0 后重新连接，让验证留在插着设备的远程电脑上。
  参考：https://learn.microsoft.com/en-us/azure/virtual-desktop/rdp-properties

查看设备里保存的网站和账号
1. 连接设备，打开“独立模式查询”页签。
2. Windows 上若显示“以管理员身份打开账号列表”，点击并允许系统的权限提示。
   只有查看账号需要管理员权限，平时登录和确认不需要。
3. 点击“输入 FIDO PIN 并读取”，输入这把安全密钥的 PIN（就是网页登录时输入的那个 PIN）。
4. 列表显示网站、账号、显示名称和用户 ID。“重新验证并刷新”会再次要求 PIN。
  这里只显示保存在设备里的通行密钥。有些网站的凭据不保存在设备里，因此不显示，但照样能登录。
  网站没有提供账号名时显示“（网站未提供）”，可以用用户 ID 区分。
  查看不会导出私钥、删除凭据或修改 PIN。PIN 和列表不保存到磁盘，PIN 输错不会自动重试。
  切换页签、最小化、锁屏、拔出设备或显示满 5 分钟后，列表会自动锁定。
  中转模式的设备不会在这里显示账号，请到“中转模式服务”中查看。

四、中转模式
准备安全端
1. 在作为安全端的电脑上打开程序，进入“中转模式服务”页签（不需要插入设备）。
2. 点击“初始化本机库”建立凭证库；若要把凭证库放在云端，见下文“云存储”。
3. 把设备插到这台安全端电脑上并按 BOOT 配对。安全端只接受在本机配对过的设备，不需要任何证书。
4. 在“授权与设置”页的“设备设置”中：
   工作模式选“中转模式”；
   用“添加”填写 Wi-Fi 名称、Wi-Fi 密码、安全端主机（域名或 IP，不带 https://）和安全端端口，
   最多 10 组，按顺序尝试；
   点击“写入设备”，设备蓝灯快闪后，先松开 BOOT，再按住至少 1 秒后松开。
   显示“配置已保存并核对一致”后拔插设备，新设置生效。
5. 回到“中转模式服务”，点击“启动中转服务”，填写监听地址和端口（默认 0.0.0.0 和 8443）。
   程序不会修改防火墙，请自行确保设备能通过 Wi-Fi 访问这个地址和端口。
   服务启动后，以后每次打开程序都会自动启动，直到你点击“停止中转服务”。
   锁屏会停止服务并锁定凭证库，解锁后请再次点击“启动中转服务”。

读取和修改设备设置
  “读取设备”把设备里已保存的设置读回程序，方便修改后再写入。Wi-Fi 密码会显示为以 PF2PW1
  开头的加密串，只有这台设备能解开。不改密码时保留这串内容直接写回；要换密码时直接输入新密码。
  连接不上时，可查看“设备设置”下方的“最近一次中转连接”，了解停在了 Wi-Fi、地址、TLS 等哪个阶段。

使用时的批准
  网页发起注册或登录时，安全端弹出“中转模式 · 确认通行密钥请求”。核对设备、网站和账号后点击
  “批准本次请求”，否则点击“拒绝”。超时、关闭窗口或锁屏都视为拒绝。

中转 PIN
  每个设备在安全端有自己的中转 PIN，和设备在独立工作模式下的 PIN 无关。
  设置或修改 PIN 时安全端会弹出“中转模式 · 确认设备 PIN 请求”；平时输入 PIN 不弹窗，
  每次注册或登录只需批准一次。
  共有 8 次尝试机会；连续输错 3 次后，需要拔插设备或重启安全端服务才能继续尝试。
  忘记 PIN：在安全端点击“停止并锁定”，再“打开凭证库”，点击“重置设备中转 PIN”并填写设备序列号。
  已保存的凭证不受影响，设备下次使用时需要重新设置中转 PIN。完成后再次点击“启动中转服务”。

切回独立工作模式
  在“设备设置”中选择“独立工作模式（默认）”并写入设备。设备里原有的本地凭证在中转期间不会改动，
  切回后可以继续使用；中转期间注册的凭证留在安全端。

精确查询账号
  命令行 pico-fido-cli --relay-query 网站 完整账号名 可以询问安全端某个账号是否存在。
  安全端弹出“中转模式 · 确认账号查询”，批准后只回答“是”或“否”，不会列出账号。

五、安全端的备份与恢复
  “创建加密备份”生成一个新的 .pf2bak 文件，包含全部凭证、计数器和中转 PIN 状态。
  备份密码 12–256 个字符，请与备份文件分开保管；没有正确的密码就无法恢复。
  本机库备份成功后，程序会询问是否清空本机库。默认“保留本机库”，关闭对话框也会保留。
  选择“清空本机库”时，程序先重新读取并核对备份，备份无法读取或与当前库不一致就不会清空。
  清空只删除本机凭证库，保留备份文件、本机授权密钥、设备配对和网络设置。
  “从备份恢复”只在本机还没有凭证库（或已按上面的方法清空）时可用，不会覆盖或合并已有的库。
  云端库没有清空选项。
  旧备份不包含之后新增的凭证和计数变化，同一时间只应使用其中一份副本。
  本机授权密钥和设备设置不在备份中。换一台电脑做安全端时，恢复备份后需要重新生成本机密钥并按 BOOT 配对。

六、云存储（可选）
  凭证库可以放在云端，供几台安全端电脑共用。除了云盘，还需要一台协调服务器（etcd），
  它负责保证同一时间只有一台电脑在修改凭证库。协调服务器和客户端证书请向部署它的人索取。
  1. 点击“配置云存储”，选择新建 WebDAV、OneDrive 或 Google Drive 配置，或更新现有配置、重新登录。
     OneDrive 和 Google Drive 在系统浏览器中登录，程序不接触你的云盘账号密码。
     Google Drive 需要你自己的桌面应用 Client ID 和应用密钥。
  2. 保存配置后，选择“建立云端库”“连接已有库”或“迁移到云端”。迁移中断时点击“恢复未完成操作”。
  恢复码：建立或迁移云端库时，程序生成一个 26 位恢复码，只显示一次，需要你再输入一遍确认。
  输入时可勾选“在此电脑上记住恢复码（使用系统安全存储）”，验证成功后安全保存，下次启动自动使用。
  Windows 使用 DPAPI，macOS 使用钥匙串保护，Linux 使用 Secret Service 保护；不会明文保存。
  记住的码无法解密云端库时会清除记录并等待重新输入；网络故障不会清除。解除本机绑定也会清除记录。
  请抄写或打印后离线保存。打开云端库、换电脑和恢复未完成操作都要用它，丢失后无法找回。
  云端只保存用恢复码加密后的凭证库，云盘数据泄露也无法被破解。
  云端无法连接、数据比之前见过的版本更旧，或校验失败时，程序会拒绝操作，不会改用本机的库。

七、设备丢失
  在“中转模式服务”中点击“撤销丢失设备”，选择设备并确认。不需要插入设备，服务运行时也可以操作。
  撤销后，这台安全端会拒绝该设备的所有新请求。找回设备后按 BOOT 重新配对即可恢复使用。
  撤销只对这台电脑、当前系统用户的安全端生效；有多台安全端时，需要在每台上分别撤销。
  撤销不会删除网站账号，也不会擦除丢失设备里在独立工作模式下保存的凭证。
  注意：拿到设备的人可以用 BOOT 配对自己的电脑，再切回独立工作模式，此时设备里的本地凭证只受
  本地 PIN 保护。如果担心设备连同 PIN 一起丢失，启用中转模式前不要在设备里保留本地凭证。
  本设备没有启用芯片级加密，能读出闪存的人可以取得设备密钥和 Wi-Fi 密码并冒充这台设备，
  但每次操作仍需安全端批准，撤销设备即可阻止。

八、刷写新设备
  “刷写新设备”用于给一块全新的 ESP32-S3 SuperMini 写入固件，或彻底重装一块设备：
  1. 拔下设备，按住 BOOT 插入 USB 后松开，设备进入刷写模式。
  2. 在窗口中确认发现的设备，勾选确认后点击“开始刷写”。完成后设备自动重启，
     然后在主窗口中选择、命名并配对它。
  刷写会清除芯片上的全部数据，包括通行密钥、配对关系和网络设置，无法恢复，也不会做备份。
  不要用它升级已经保存了账号的设备。刷写开始后不要中途取消，否则需要重新刷写才能使用。

九、在常用网站登记
Google 账号
  打开 https://myaccount.google.com/signinoptions/passkeys
  创建通行密钥 → 换部设备/使用其他设备 → USB 安全密钥，输入安全密钥 PIN 后按 BOOT 或在程序中确认
  （中转模式下在安全端批准）。
  如果更喜欢“密码 + 安全密钥”两步验证，可启用两步验证，并在账号安全设置中关闭
  “尽可能跳过密码输入步骤”。
  新增的通行密钥可能要等一段信任期，请趁现在还能登录时提前登记，并实际试一次登录。
  官方说明：https://support.google.com/accounts/answer/13548313?hl=zh-Hans

个人 Microsoft 账号
  打开 https://account.microsoft.com/security
  高级/更多安全选项 → 添加新的登录或验证方式 → 使用安全密钥 → USB，输入或设置安全密钥 PIN，
  按 BOOT 或在程序中确认，并给密钥起个名字。登录时在“登录选项”中选择安全密钥。
  工作或学校账号能否使用，取决于所在组织的设置。
  官方说明：https://support.microsoft.com/en-gb/security/sign-in-to-your-account-with-a-security-key

Apple 账号
  Apple 要求至少两把带 FIDO Certified 标志的安全密钥，本设备没有获得认证但可以兼容，测试可用。
  iPhone 通过 USB-C 在网站上注册和登录可以使用；Lighting 接口需要 OTG 转接头。
  官方说明：https://support.apple.com/zh-cn/102637

十、重要提醒
  本设备使用自制固件，没有经过独立安全审计或 FIDO 认证，也没有启用防拆、Secure Boot 或闪存加密。
  安全密钥能增加一种不依赖手机号的登录方式，但不能保证绕过网站的风控、账号锁定或恢复审核。
  请为每个重要账号保留另一种独立的恢复方法，以免设备损坏、丢失或安全端不可用时无法登录。

十一、附录
程序数据位置（卸载或排查时参考；不要手动复制这些文件到其他电脑）
  Windows：%LOCALAPPDATA%\PicoFido2Remote
  macOS：~/Library/Application Support/PicoFido2Remote
  Linux：~/.local/share/PicoFido2Remote（或 $XDG_DATA_HOME/PicoFido2Remote）
  敏感数据都经过加密：Windows 上绑定当前用户账户；macOS 和 Linux 上的密钥保存在系统钥匙串
  （macOS 钥匙串、GNOME Keyring 或 KWallet）。钥匙串不可用时程序会拒绝保存，不会以明文保存。

Linux 设备权限
  普通用户访问安全密钥需要一条 udev 规则。新建 /etc/udev/rules.d/70-pico-fido2.rules，内容为：
    KERNEL=="hidraw*", ATTRS{idVendor}=="1d50", ATTRS{idProduct}=="619b", TAG+="uaccess"
  然后运行 sudo udevadm control --reload 和 sudo udevadm trigger，并重新插拔设备。
  程序本身不需要以管理员身份运行。
